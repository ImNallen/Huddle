# Design System: Huddle

## Overview

**Creative North Star: "The Known Floor Plan"**

A Discord user should know where everything is at first sight. Huddle deliberately follows Discord's desktop shell, at the user's request, and plays it straight: a rail of rounded-square tiles, a channel sidebar, a flexible chat, a member list, a composer at the bottom, and an account panel floating across the rail and sidebar. Recognition is the design. Nothing here competes with that layout for attention, and the shell asks nothing of the people chatting in it.

Huddle keeps its own name and logo and uses no Discord logo, art, or font. The typeface is Figtree, bundled through `@fontsource-variable/figtree`. The result is a dense, flat room: a shell around a slightly lifted chat ground, one blue accent, and full-width messages with no bubbles. It replaces Huddle's earlier quiet SaaS arrangement of breadcrumbs, bubbles, and a centered message column.

The interface shows only what exists. Controls for unbuilt features (search, emoji, attachments, presence) are deliberately absent, so a familiar layout never promises something the server cannot do. A voice channel on a server with voice off, or in the desktop app, says so and has no call controls. The scheme follows the system until someone chooses otherwise in Settings. Colors follow T3 Code's, in both schemes, and a person can pick, create, or import other themes on their own device.

**Key Characteristics:**

- A fixed floor plan that a Discord user reads without learning it.
- Flat, full-width messages on a slightly lifted ground inside a darker shell.
- One accent for action, focus, and the current place on the rail.
- Hairlines and tonal steps for structure; shadows only where something floats.
- Figtree throughout, with a tight type ramp and a 14px interface base.
- Only built features have controls.

## Colors

The default theme is called Huddle. A near-black neutral family carries one saturated blue, with status colors reserved for state and eight bright mascot colors reserved for people. Its values take T3 Code's as their reference. `src/chat.css` declares every color token once, as `light-dark(light, dark)`, so one rule holds both schemes and a token never needs a second copy. Below, each value is given as light then dark.

### Primary

- **Huddle Blue** (`accent`: #1b4ed8, #346bf1): Primary buttons, the current or hovered rail tile, input focus borders, the composer send icon, the text caret, and selection tint. White text sits on it (#ffffff).
- **Pressed Blue** (`accent-hover`: #3160db, #3061d9): Primary button hover.
- **Focus Ring** (`focus`: #1b4ed8, #346bf1): The 2px keyboard focus outline on controls and fields. The composer's text area is the one exception; see Composer.
- **Link Blue** (`link`: #1b4ed8, #51a2ff): Text links and quiet actions such as "Change".
- **Mention Tint** (text: #1a43b8, #b4cbff; fill: 12% and 28% accent): @mentions in messages and the accent tag.

### Secondary

Status colors, not a second brand voice.

- **Connected Green** (`green`: #116b36, #23a55a): The account panel's connected dot, finished setup steps, the copied state, and being in a call: the call panel's status and the channel row's icon.
- **Waiting Amber** (`amber`: #a34300, #ffb900): The account panel's not-connected dot, warning notices, and a call that is reconnecting.
- **Soft Danger** (`danger`: #c10007, #ff6467): Error text, failed messages, invalid input borders, destructive actions, and a muted microphone.
- **Count Red** (`danger-fill`: #c10007, #d92d36): The unread count badge on the rail, with white numerals, and the Delete theme button.

### Tertiary

- **Mascot Set** (indigo #818cf8, sky #38bdf8, teal #2dd4bf, lime #a3e635, amber #fbbf24, orange #fb923c, rose #fb7185, violet #c084fc): The eight colors a person can give their mascot avatar. They mark people, appear on no other surface, and never change with a theme. They are Huddle's own, carried in `src/Avatar.tsx`.

Server badges are tinted by hash: a hue from a set of eight, with lightness set by the scheme through `light-dark()` (text at 34% in light and 72% in dark; fill at 90% and 18%). Fallback initial avatars use the same lightness at a fixed hue of 250. Badges read the scheme, not the theme.

- **Scrim** (55% white in light, 70% black in dark): The backdrop of every dialog, which also blurs the app behind it by 8px. It drops away while the create panel is open, so a live preview shows on the real app.

### The theme system

A theme is one or two **halves**, one per scheme. A half is a seed of `background` and `accent` plus `overrides`, a partial map of tokens. `TOKENS` in `src/appearance/palette.ts` is the one table of color tokens: its rows hold each token's label, group, T3 Code and VS Code keys, derivation, and contrast floor. The resolver, the Advanced editor, and both importers all read it, and a check fails the build if `src/chat.css` disagrees with it in either direction. Add a token by adding a row and a `chat.css` line.

Huddle is the one theme in CSS. The other five built-ins, Indigo, Moss, Harbor, Clay, and Plum, are seed data resolved the same way custom themes are. Indigo is the palette Huddle had before it took T3 Code's colors, so upgrading deletes no look. A selection pointing at a deleted theme or a missing half reads as Huddle.

Three states pick the side. No `data-scheme` on `<html>` means System: `color-scheme: light dark` and `light-dark()` follow the OS live with no JavaScript. `data-scheme` set to `light` or `dark` forces it, including native controls. An adopted stylesheet carries a custom half's tokens, and it targets `:root` only, so `[data-palette='huddle']` still reads Huddle from CSS under any theme. Swatches and scheme previews rely on that.

Shadows, the scrim, and badges follow `color-scheme` through `light-dark()`. A theme holds colors only.

A color reaches a stylesheet only as a `ColorLiteral`, which only `parseColor` mints. Its only outputs are `#rrggbb` and `rgb(r g b / a)`, built from parsed numbers and never from the input text, because tokens flow into `background:` shorthands where `url()` would make a request.

### Named Rules

**The T3 Reference Rule.** Huddle's values are T3 Code's where T3 has that role. A departure needs a measured reason. T3's light `textMuted` #71717b reaches only 4.39:1 on #f4f4f5, which Huddle uses for the panel, shell, and composer, so light uses #62626c. White on T3's `error` reaches 3.81:1 in light and 3.53:1 in dark, and the unread count is white on `danger-fill`, so those are darkened. T3's `input` is a border, so it maps to `line-strong`.

**The Readable Theme Rule.** Body text, muted text, and accent foreground keep at least 4.5:1 on every ground, and the focus ring 3:1, in every theme. Comparison runs on the 8-bit value that will be written. Derivation seats a seed background so that pure white or black reaches 4.75:1, and a guarded token moves until it clears its floor. An imported file's overrides are guarded too, because a file is not a person's choice. Advanced edits are the one exception: they stay verbatim and show their ratio.

**The One Accent Rule.** The accent marks action, focus, and the current place on the rail. It is never a panel ground, and no second accent exists.

## Typography

**Display Font:** Figtree Variable (with -apple-system, BlinkMacSystemFont, SF Pro Text, Inter, and system-ui as fallbacks)
**Body Font:** Figtree Variable
**Label/Mono Font:** ui-monospace (with SF Mono, SFMono-Regular, and Menlo as fallbacks), for hostnames, invite codes, and Tailscale logins

**Character:** One friendly geometric sans at every level, bundled through `@fontsource-variable/figtree`, so the familiar layout does not depend on Discord's proprietary face. Hierarchy comes from weight and color more than size.

### Hierarchy

- **Display** (700, 32px, 1.25): The channel welcome heading only, dropping to 24px at 760px wide.
- **Headline** (700, 24px, 1.25): Home greeting and the Members page.
- **Headline Access** (600, 24px, 1.25): The centered heading on the access card.
- **Title Dialog** (700, 20px): Centered dialog headings.
- **Title** (600, 16px): Channel name in the top bar, the current tab in the Settings window's top bar, server name in the sidebar, message authors, and card headings, including "Direct messages" on Home.
- **Body** (400, 16px, 1.375): Message text and the composer. Lines run the full width of the chat column.
- **Nav** (500, 15px): Channel rows, member rows, and settings navigation.
- **UI** (400, 14px, 1.375): The interface base, set on the root. Weight 500 (`ui-strong`) for buttons, menu items, tabs, and field labels.
- **Section Label** (500, 12px, mixed case): "Text Channels", member group headings, and the "Settings" label. Table headers use the same size at 600.
- **Meta** (400, 12px, tabular numerals): Timestamps and counts, in `faint` or `muted`. The hover-revealed continuation time uses 11px.
- **Access Label** (700, 12px, 0.02em, uppercase): Field labels on the access card and the saved servers list label.

### Named Rules

**The One Family Rule.** Figtree sets everything people read as language. Monospace appears only for machine values such as hostnames and invite codes.

**The Quiet Label Rule.** Shell labels stay 12px and mixed case. Uppercase belongs to field and list labels inside the access card, and nowhere in the shell.

## Layout

The shell is a fixed floor plan on a CSS grid filling the viewport below the window bar (minimum window height 480px): 72px rail, 248px channel sidebar, flexible chat, and 240px member list, all under a 32px title bar. In the browser it is a grid row showing the server. In the desktop app `WindowBar` replaces it with a fixed bar over every screen, and `:root[data-native]` collapses the row and sets `--window-bar-height`.

The sidebar header and top bar share a 48px height, so one horizontal line runs across the top of the shell. The account panel is absolutely placed 8px from the bottom left, spanning the rail and sidebar minus 16px; the rail stops 72px above the window bottom and the sidebar reserves 80px of bottom padding, so nothing scrolls under it.

The thread runs full width with no measure: messages are inset 72px on the left to clear the 40px avatar, and 48px on the right. Pages within the chat column are narrower by purpose: Home is a centered 680px column, its setup state 440px; Members is a left-aligned table up to 880px. The Settings window centers its content in a column of up to 680px. Dialogs are 460px and the access card 480px.

Spacing runs on 8px with 2, 4, 6, 12, and 20px steps for tight assemblies. Density is high: nav rows are 32px, and author groups are separated by 16px while continuation lines stack with none.

Responsive changes are progressive. At 1000px the member list and its toggle disappear. At 760px the rail narrows to 56px, the sidebar to 200px, rail tiles to 36px, and the Settings side column to 168px. At 560px the access header shrinks, and the Settings window fills the space below the window bar with an 8px margin and stacks under a horizontal nav. At 480px the rail is 48px, the sidebar 130px, and the rail tile 32px, Home's conversation rows drop their avatars and unread tags, and the Appearance theme grid drops to two columns.

## Elevation & Depth

A hybrid that is flat by default. The shell is built from tonal steps and hairlines; the chat ground sits one step above the shell, and the top-left corner of the sidebar is rounded 8px so the content area reads as a sheet set into the chrome. Shadows appear only on things that float above the shell, and on the card lifted off the access field. The account panel floats by position, with a hairline border and no shadow.

### Shadow Vocabulary

- **Menu** (`box-shadow: 0 8px 24px rgb(0 0 0 / 0.4)` dark, `0 8px 24px rgb(24 24 27 / 0.16)` light): Server menu and rail tooltips.
- **Modal** (`box-shadow: 0 16px 48px rgb(0 0 0 / 0.5)` dark, `0 16px 48px rgb(24 24 27 / 0.24)` light): Dialogs, over the scrim, and the create panel.
- **Access Card** (`box-shadow: 0 4px 16px rgb(0 0 0 / 0.35)` dark, `0 4px 16px rgb(24 24 27 / 0.2)` light): The card on the access field.

### Named Rules

**The Flat Shell Rule.** Rail, sidebar, chat, member list, and account panel carry no shadow. A shadow means the element is temporarily above the shell or sits on the access field.

## Shapes

Gently rounded rectangles at a small set of radii: 4px for menu items, mentions, and tags; 6px for rows, tabs, and icon buttons; 8px for buttons, inputs, cards, the composer, and the account panel; 12px for dialogs. People and channels are round: avatars, presence dots, and channel marks use 50%. Servers are rounded squares: rail tiles at 12px, tightening to 10px on hover, with server badges at 30%.

Mascot avatars are the system's one playful form: a rounded square (28%), circle, hexagon, triangle, bean, or flower in a mascot color, with two white vertical pill eyes. The Huddle logo is a circle cut by vertical slots and renders in `currentColor`.

Motion is small and shared: 120ms for color and border changes, and `cubic-bezier(0.16, 1, 0.3, 1)` for rail pill height, tile radius, tooltip movement, and dialog entrances. A dialog and its backdrop fade in over 140ms, the dialog also from 98% scale, with no exit animation. Reduced motion removes transitions and that entrance.

## Components

### Buttons

Compact and plain, with fill as the only emphasis.

- **Shape:** Gently rounded (8px), 38px tall with 16px side padding, or 32px and 12px at small size. Access card buttons are full-width at 44px and 16px type.
- **Primary:** Accent fill with `on-accent` text, moving to `accent-hover`.
- **Danger:** Count Red fill with `on-accent` text, for confirming a deletion.
- **Secondary:** Secondary Fill with `text`, moving to its hover step.
- **Text:** No fill, underlined on hover.
- **Icon:** 32px square at 6px radius, `muted` turning `text` over the hover wash.
- **Focus / Disabled:** 2px Focus Ring at 2px offset; 50% opacity when disabled.

### Tags

- **Style:** 12px, weight 500, 1px by 6px padding, 4px radius, on Secondary Fill.
- **State:** The accent variant uses Mention Tint for mentions and the Admin role.

### Cards / Containers

- **Corner Style:** 8px, or 12px for dialogs.
- **Background:** Card Surface in the app, Raised Surface for dialogs, Access Card on the access field.
- **Shadow Strategy:** None in the app. See Elevation & Depth for dialogs and the access card.
- **Border:** 1px hairline in the app and on dialogs. The access card has none.
- **Internal Padding:** 16px in settings cards, 24px in dialogs, 32px on the access card (24px at 560px wide).

### Inputs / Fields

- **Style:** 40px tall, 8px radius, 12px side padding, with a `line-strong` border on the chat ground. Access card inputs drop the border for a filled `access-input` at 16px type.
- **Focus:** The Focus Ring plus an accent border; access card inputs add a matching 1px ring.
- **Error / Disabled:** `danger` border, with a 1px danger ring on the access card when focused. Disabled inputs take `panel` and `muted`.

### Navigation

- **Rail:** Rounded-square tiles on the shell. The Home tile holds the Huddle logo, a separator follows it, then one tile of initials per room, then a Create room tile for admins and a Switch server tile when the app offers it. Hover and current fill the accent. The Home tile's red count is the total of unread direct messages. A room tile keeps the unread pill and adds the same red count for its unread mentions; its accessible name stays the room name and its description carries the numbers, such as `2 unread, 1 mention`. The rail scrolls with its scrollbar hidden, and one fixed tooltip follows the hovered or focused tile so scrolling never clips it.
- **Rail Pill:** A 4px marker in `strong` on the rail's left edge: 8px when unread, 20px on hover or focus, 32px when current.
- **Channel rows:** 32px rows of 15px type with an 18px hash icon, or a speaker for voice channels, in `muted`. Hover adds the wash and `text`; current takes `selected` and `strong`; unread takes `strong` and an 8px pill at the sidebar's edge. A channel with unread mentions adds a small red count at the row's end. The speaker turns `green` on the channel you are in a call in.
- **Direct message rows:** At Home, Members, and direct views the sidebar lists a "Direct Messages" section under Members, with a `New message` add button for everyone. Rows are 42px with a 24px avatar and the peer's name, and use the channel row states. The empty text is "No messages yet."
- **Section labels:** "Text Channels", "Voice Channels", and "Direct Messages" at 12px, with a small 24px add button.
- **Top bar:** 48px with the channel icon and name at 16px, and page actions at the right. It states the current place directly, with no breadcrumb trail.
- **Settings:** A 200px side nav with the same row states under a "Settings" label. The right column has a 48px top bar with the current tab's title and an icon button that closes the window.

### Home

Home is about direct messages. Room activity lives on the rail, so Home has no feed, tabs, or mark-all. While setup is incomplete it holds the checklist. After that it holds the greeting, the date, and a "Direct messages" list. Rows hold a 32px avatar, the name, the time, a one-line preview, and an accent tag such as `2 new`; a read row's preview drops to `muted`. With no conversations it shows "No messages yet" and a primary `New message` button.

### Direct conversation

Direct views share the channel transcript and composer. The top bar holds a 24px avatar and the peer's name, with no member toggle, and the member list stays hidden. The welcome block holds a 68px avatar, the name as its heading, the start-of-conversation line, and a smaller muted line saying the host could read stored messages. The `New message` dialog lists every other member as a row with a 32px avatar. In the member list, rows for other members are buttons named `Message {name}`.

### Message

The signature surface. Messages are flat and full width, never in bubbles.

- **Grouped:** Author row with a 40px avatar, 16px weight 600 name, and a 12px tabular time; continuation lines drop the header and sit flush.
- **Hover:** A 3% wash across the full row, and continuation lines reveal an 11px time in the left gutter.
- **Pending / Failed:** Sending text drops to 50% opacity; failed text turns `danger` with its error below.
- **Day dividers:** Hairline rules on either side of a 12px centered date.

### Composer

- **Style:** A filled 52px bar at 8px radius, inset 16px from the chat edges with 24px below, growing with its content to half the viewport.
- **Contents:** A 16px text area and the send icon only, in the accent when ready and `muted` when empty.
- **Focus:** A 1px `line-strong` ring around the bar.

### Account Panel

A 56px hairline-bordered panel across the rail and sidebar: 32px avatar, name at 14px weight 600, a 12px role or connection line, and a settings icon. It holds the only presence dot in the product, 12px and ringed in `panel`. Green means connected and amber means not connected; the dot reflects connection state and says nothing about other people.

### Voice

- **Voice channel page:** Centered in the chat column. The channel mark, name, one line of state, and one button, which stays in place as Join voice, Cancel, Leave call, or Try again, so focus survives each change. In a call the mark gives way to a row of people, each a 56px avatar over a 14px name, with a 22px mic-off badge at the avatar's corner when muted. A failure replaces the line with its explanation in `danger`.
- **Call panel:** A panel like the account panel, floating 8px above it from the moment someone joins until the call ends. It holds a 14px status in the state's color, the 12px channel name, a Mute toggle, and Leave call. The status and name are a button that opens the channel. A failed call stays here with a Dismiss button until it is dismissed or its channel opened, except that it stays out of the way while that channel is on screen. When a browser blocks playback, a full-width Turn on sound button joins it. At 480px wide its controls drop to a second row. The rail and sidebar reserve its height, so nothing scrolls under it.

### Member List

240px of `sidebar` ground, with 12px mixed-case group labels ("Admins — 1") above 42px rows holding a 32px avatar and a 15px weight 500 name in `muted`. Rows carry no presence dots.

### Menus and Dialogs

- **Menu:** 220px on Raised Surface at 8px radius with an 8px inset, 32px items at 4px radius, and icons at the row's trailing edge.
- **Dialog:** 460px on Raised Surface at 12px radius over the Scrim, with a centered 20px heading and description and right-aligned actions.
- **Settings window:** Up to 920 by 680px on Account Panel Ground at 12px radius, with a hairline border and the Modal shadow, over the Scrim. It centers in the space below the window bar and keeps the app mounted behind it. The left column uses the `sidebar` ground behind a hairline, and the right column scrolls below its top bar.

### Appearance

Settings' Appearance tab sits between Profile and Connection and renders outside the account gate, because it needs no server. Everything on it is per device.

- **Scheme cards:** Three radio cards in a `radiogroup` named Color scheme, each a small flat floor plan (rail, sidebar, chat lines, composer dot) in the selected theme's colors. System is split down the middle. A checked card takes a 2px accent border.
- **Theme cards:** A three-column grid of 8px cards on `card`, with the theme's swatches centered above its name, a copy icon button named `Copy {name} as JSON`, and, on custom themes, a delete icon button. Built-ins cannot be deleted.
- **Swatches:** Native radios named `{theme} light` and `{theme} dark`, grouped by side, styled as 36px soft orbs: a radial gradient from that half's `--bg` and `--accent`. The selected one takes a 2px accent ring with a 3px gap and a sun or moon badge. A swatch choice never changes the mode. A status line says when a choice is not on screen.
- **Create panel:** A 340px floating panel at the window's bottom right on Raised Surface, a nested modal dialog with no backdrop of its own. It holds a name, Appearance, Background, and Accent, with an Advanced switch that lists `TOKENS` by group. It previews live on the real app, so the Settings scrim drops away while it is open, and Settings stays inert. A stray click on the backdrop does not discard a draft. Cancel and Escape restore exactly the prior state. Saving merges a missing half into a same-named theme, and if the new half would not be on screen under the current mode, it switches the mode.
- **Edit theme:** The create panel, opened from the pencil on a custom theme's card. Built-in themes have no pencil. The Appearance switch moves between the theme's sides and keeps both drafts, and a side the theme lacks is added only if it is saved or changed. Saving selects the edited side and never moves the mode, so an off-screen edit reports where it shows.
- **Add a theme:** A wider dialog (620px) that opens on Search community themes, with Popular shortcuts, a Sort menu that starts on Most relevant, and a two-column grid of result cards that scrolls on its own past 340px. Results list only extensions with a color theme. Install adds every variant at once, pairs a family's one light and one dark into one card, and closes the dialog, and the Appearance status offers Undo until the next change. Below a divider sit a dashed file row and a Theme JSON text area. A file dropped anywhere in the window is read while it is open. It reads T3 Code and VS Code theme files, including JSONC, and refuses the whole file if a color it would read is not a literal, naming the role.

### Access Screens

Setup, join, and the screens that explain a missing identity share one frame: the Access Field gradient, a logo and lowercase "huddle" wordmark in a 72px header, and a centered 480px Access Card. A server card at the top of the access card identifies the destination with a tile, name, and monospace host.

## Do's and Don'ts

### Do:

- **Do** place every shell zone where a Discord user expects it: 72px rail, 248px sidebar, flexible chat, 240px member list, composer at the bottom, account panel floating across rail and sidebar.
- **Do** keep the Huddle name and logo on the rail and access screens.
- **Do** set messages flat and full width, with authors grouped and continuation lines flush.
- **Do** use the Rail Pill lengths exactly: 8px unread, 20px hover or focus, 32px current.
- **Do** read every color from the tokens so every theme resolves, and define a new role as one `light-dark()` line in `src/chat.css` and one row in `TOKENS`.
- **Do** use Lucide line icons, mostly at 16 to 20px, in `muted`, moving to `text` or `strong` with state.
- **Do** build separation from hairlines and tonal steps before reaching for a shadow.
- **Do** draw the merged 32px window bar over every desktop screen, with traffic lights on macOS and drawn controls elsewhere.

### Don't:

- **Don't** use Discord's logo, illustrations, or proprietary font.
- **Don't** add controls for features that are not built, including search, emoji, attachments, and presence.
- **Don't** show a presence dot anywhere but the account panel, or use it for anything but connection state.
- **Don't** put messages in bubbles or constrain the thread to a centered column. Home, setup, and settings may still use a readable column.
- **Don't** add breadcrumbs to the top bar.
- **Don't** uppercase labels in the shell.
- **Don't** add a resting shadow to the rail, sidebar, chat, member list, or account panel.
- **Don't** use a gradient outside the access field and the Appearance swatches, the one exception, whose gradient is built from that half's own `--bg` and `--accent`.
- **Don't** branch on the scheme with a media query. Use `light-dark()`, which accepts colors only, so a lightness or shadow pair is written as two full colors.
- **Don't** paint a theme's value from a string that has not been through `parseColor`.
